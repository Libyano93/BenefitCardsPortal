# بوابة بطاقات المستفيدين

تطبيق ASP.NET Core MVC على .NET 9 لرفع دفعات كشوف البطاقات، مراجعتها، والبحث في السجلات مع متابعة الاستلام. التخزين المحلي يستخدم SQLite لتسهيل التشغيل من VS Code دون تثبيت SQL Server.

## الموجود في النسخة الحالية

- واجهة عربية RTL للمواطن والموظف.
- صفحة رئيسية بإحصاءات عامة للكشوف المعتمدة وحالة التسليم، ورسمة توضيحية أصلية للأسرة والبطاقات.
- لوحة موظف بمؤشرات ومخططات لحظية وإدارة جميع الدفعات.
- دخول موظفين عبر ASP.NET Core Identity، مع قفل مؤقت بعد محاولات فاشلة.
- رفع ملفات PDF/PNG/JPG إلى مجلد خاص خارج `wwwroot`، مع التحقق من نوع الملف الفعلي وحجم 20 ميغابايت.
- استخراج آلي محلي بالعربية والإنجليزية من الصور وصفحات PDF، ثم عرض الصفوف في شاشة مراجعة قابلة للتعديل.
- مطابقة أعمدة كشف الوزارة: الرقم، رقم التسلسل، اسم المستفيد، الاسم على البطاقة، جزء من رقم البطاقة، جزء الرقم الوطني، والملاحظات.
- اختيار الملف يبدأ القراءة تلقائيًا ويعرض معاينة قابلة للتحرير قبل حفظ أي دفعة.
- خط Cairo محلي وواجهة RTL ملونة؛ صف البطاقة أخضر بعد الاستلام وبرتقالي قبله.
- تأكيد إضافي برمز منفصل قبل حذف أي دفعة؛ تبقى الدفعة ظاهرة لكن لا يمكن حذفها حتى ضبط الرمز.
- دفعة مستقلة لكل كشف وشهر/سنة؛ لا تُستبدل الدفعات السابقة.
- إضافة ومراجعة سجلات كل دفعة، واعتمادها قبل ظهورها في بحث المواطن.
- حالة استلام مستقلة لكل بطاقة مع وقت الاستلام وحساب الموظف.
- لا يمكن تسجيل الاستلام قبل اعتماد الكشف، مع التحقق من ذلك في الواجهة والخادم.
- بحث بالاسم أو بالجزء المتوفر من الرقم الوطني.
- تحديد محاولات البحث العامة بـ 12 طلبًا في الدقيقة لكل مستخدم أو عنوان اتصال للحد من إساءة الاستخدام.
- تقرير موظفين لتسليمات البطاقات والتراجعات مع تصفية حسب الفترة والحالة، وتصدير CSV متوافق مع Excel وطباعة المتصفح إلى PDF.
- فحص جودة آلي للكشف والتنبيه إلى النواقص والتكرار قبل الاعتماد.
- سجل عمليات الموظفين مع تصفية حسب العملية والموظف والتاريخ.
- فلاتر للدفعات والسجلات حسب الشهر والسنة والاعتماد والاستلام.
- إخفاء الرقم الوطني في خانة بحث المواطن وعدم عرضه في النتائج.
- شاشة إعدادات للمسؤول تضبط بريد التنبيه وتفعيل المسح ومدة الاحتفاظ بالساعات أو الأيام.
- إدارة حسابات الموظفين مع دور موظف ودور مسؤول، ومنع إزالة آخر مسؤول أو صلاحية حساب المسؤول الحالي.

## التشغيل في VS Code

من مجلد المشروع نفّذ في الطرفية:

```powershell
$env:InitialEmployee__Email = "staff@example.local"
$env:InitialEmployee__Password = "ChangeThis123!"
$env:InitialEmployee__MakeAdmin = "true"
$env:BatchDeletion__Passcode = "ضع-هنا-رمزًا-خاصًا-لا-يقل-عن-8-محارف"
dotnet restore
dotnet run
```

افتح عنوان `localhost` الذي يظهر. غيّر بيانات المثال إلى بريد وكلمة مرور خاصة بالموظف قبل الاستخدام. في وضع Development ينشئ التطبيق قاعدة SQLite تلقائيًا داخل `App_Data`.

## إعدادات الموظفين والتنبيهات

الحساب الأول الذي تضبط له `InitialEmployee__MakeAdmin=true` يحصل على صلاحية مسؤول النظام. يسجل المسؤول الدخول ثم يفتح **إدارة الموظفين** لإنشاء حسابات موظفين أو منح/إزالة صلاحية المسؤول. يمكن إسناد صلاحية **إدارة إعدادات النظام والبريد** لموظف من قائمة الصلاحيات؛ المسؤول لديه جميع الصلاحيات تلقائيًا. في Development هذه الصلاحية مفعلة للحساب الأول تلقائيًا.

من شاشة **الإعدادات** يحدد المسؤول بريد التنبيهات ومدة الاحتفاظ بسجل العمليات، بالساعات أو الأيام، ويشغل/يوقف التنظيف. يفحص التطبيق السجل كل دقيقة، ويرسل إشعارًا قبل حذف السجلات التي تجاوزت المدة. لا يحذف السجل إذا لم ينجح إعداد البريد.

يمكن للمسؤول ضبط خادم SMTP من **الإعدادات ← إعدادات البريد** ثم إرسال رسالة تجريبية. تُحفظ كلمة مرور SMTP مشفرة عبر ASP.NET Data Protection، وتبقى مفاتيح الحماية في `App_Data/DataProtectionKeys`؛ احتفظ بهذا المجلد مع قاعدة البيانات ولا تحذفه عند إعادة تشغيل التطبيق. يمكن لمسؤول الاستضافة بدلًا من ذلك ضبط SMTP في متغيرات التشغيل، ولا تُحفظ كلمة المرور في ملفات المشروع:

```powershell
$env:Smtp__Host = "smtp.example.org"
$env:Smtp__Port = "587"
$env:Smtp__EnableSsl = "true"
$env:Smtp__FromAddress = "portal@example.org"
$env:Smtp__UserName = "portal@example.org"
$env:Smtp__Password = "كلمة مرور أو رمز تطبيق SMTP"
```

احذف `Smtp__UserName` و`Smtp__Password` إذا كان خادم المؤسسة يقبل الإرسال الداخلي دون مصادقة. إذا لم تُحفظ قيمة في شاشة إعدادات البريد، يستخدم التطبيق قيمة متغير التشغيل المقابل عند ضبطه. أرسل رسالة تجريبية وتحقق من وصولها قبل الاعتماد على التنبيهات الدورية.

## استيراد الكشف

بعد اختيار الملف تبدأ القراءة، وتظهر الصفوف بترتيب أعمدة الكشف نفسه قابلة للتعديل قبل حفظ الدفعة. تتم ترقية قاعدة SQLite تلقائيًا بإضافة أعمدة الاسم على البطاقة ورقم الصف والملاحظات عند تشغيل الإصدار الجديد. تدعم القراءة تخطيطي الكشف مع وبدون عمود الملاحظات. لا تُدمج الدفعة مع أي كشف سابق، ولا تُرسل الملفات إلى خدمة OCR خارجية. قد تتأثر الدقة بجودة المسح، لذا راجع الأسماء والأرقام. تفاصيل مصدر النماذج وترخيصها في `tessdata/NOTICE.txt`، ومصدر خط Cairo في `wwwroot/fonts/NOTICE.txt` و`wwwroot/fonts/OFL.txt`.

رمز الحذف المحلي في بيئة Development هو `KhiyarDelete#2026`. عدّله في `appsettings.Development.json` قبل الاستخدام الفعلي. يمكن تجاوز إعداد التطوير بمتغير البيئة `BatchDeletion__Passcode`. يلزم إعادة تشغيل التطبيق بعد تغييره. لا تستخدم إعداد التطوير عند نشر النظام.

## المجلدات

- `Models`: كيانات قاعدة البيانات ونماذج الواجهات.
- `Data`: سياق EF Core وترقية أعمدة SQLite عند بدء التشغيل.
- `Services`: منطق البحث.
- `Security`: حسابات الموظفين والأدوار.
- `Controllers` و`Views`: مسارات MVC وواجهات المستخدم.

## تغييرات الحسابات وتجربة الاستخدام

- عند إنشاء موظف جديد تكون كلمة المرور المدخلة مؤقتة؛ يُلزم النظام الموظف بتغييرها عند أول دخول، ويحوّله إلى شاشة التغيير حتى إتمامها.
- تنشأ الحسابات وتتغير كلمات المرور عبر ASP.NET Core Identity؛ يخزن Identity ناتج `PasswordHasher` في `PasswordHash`، ولا يخزن كلمة المرور الأصلية في قاعدة البيانات.
- من شاشة إدارة الموظفين يمكن تعطيل الحساب أو إعادة تفعيله. التعطيل يمنع الدخول فورًا، ويحفظ الحساب وصلاحياته وسجل عملياته، ولا يسمح بتعطيل المسؤول الأخير النشط أو حساب المسؤول الذي يستخدم الشاشة.
- أثناء معاينة الكشف يظهر تنبيه عند وجود دفعة سابقة بالشهر والسنة نفسيهما. يطلب النظام تأكيدًا صريحًا قبل رفع الدفعة الجديدة المستقلة.
- جرى تكييف شاشة معاينة الكشف والبحث وإدارة الموظفين مع الشاشات الصغيرة، مع عرض صفوف المراجعة كبطاقات قابلة للتمرير الرأسي على الهاتف.
- يبحث النظام بالأسماء بعد توحيد أشكال الألف والياء وإزالة التشكيل والتطويل، ويطابق كل كلمة من عبارة البحث؛ وتُفهرس خانة الاسم الموحّد لتسريع البحث.
- ترقية قاعدة البيانات عند بدء التشغيل تضيف حقلي تفعيل الحساب وتغيير كلمة المرور المؤقتة إلى جدول المستخدمين القائم، مع إبقاء الحسابات الحالية نشطة افتراضيًا.

## النسخ الاحتياطي

ينشئ النظام نسخة يومية افتراضيًا عند 02:00 بتوقيت ليبيا، ويحتفظ بنسخ آخر 30 يومًا. يمكن تعديل الموعد ومدة الاحتفاظ، أو إنشاء وتنزيل نسخة فورية من **الإعدادات ← نسخ قاعدة البيانات**. يحتوي الأرشيف على نسخة SQLite متسقة وملفات الكشوف المرتبطة بالدفعات. انقل الأرشيف ومجلد `App_Data/DataProtectionKeys` إلى وسيط آمن خارج جهاز التطبيق؛ فمفاتيح الحماية لازمة لفك تشفير إعداد SMTP عند استعادة قاعدة البيانات.
